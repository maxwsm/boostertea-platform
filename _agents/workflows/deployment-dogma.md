# 🏛️ COLIZEUM: Догма Одиночного Деплою (Заборона Паралельних Процесів)

Цей документ фіксує критичний урок, отриманий внаслідок конфліктних деплоїв (коли один агент перетер зміни іншого, що призвело до поломки корзини і редиректів на продакшені).

> [!CAUTION]
> **ЗОЛОТЕ ПРАВИЛО:** Завжди запускати **виключно один** активний процес деплою (або одного AI-агента, що працює з `main`) в один проміжок часу. 

## Чому це важливо?
Паралельна робота декількох агентів чи розробників над гілкою `main` майже гарантовано призводить до:
1. **Знищення та перетирання коду:** Зміни, щойно зафіксовані в коміті одним агентом, не підтягуються іншим агентом перед наступним пушом.
2. **Неможливості знайти "хвіст":** Сайт падає на продакшені, Vercel видає помилки, і розробнику доводиться вручну перебирати Merge Conflicts в консолі.
3. **Хибних підтверджень:** Один агент рапортує про успішний деплой, але його код насправді викреслений наступним комітом-перехоплювачем іншого агента за секунду потому.

## Суворий Пайплайн (Workflow)
Щоб уникнути цього, перед кожним початком роботи (або після завершення Правила 5 Задач), завжди виконуйте наступні кроки:

1. Заморозити роботу інших терміналів/сесій/агентів.
2. Синхронізувати локальний репозиторій з продакшеном:
// turbo
3. `git pull --rebase origin main` (або `git reset --hard origin/main`, якщо попередній агент залишив "хлам").
4. Впровадити атомарні зміни та протестувати локально або запустити білд.
5. Запушити зміни: `git add . && git commit -m "fix/feat: update" && git push`
6. Переконатися у Vercel / Contabo, що білд успішно зарелізився та засвітився "зеленим".
7. Лише після "зеленого" статусу (Success) можна віддавати `main` наступному агенту.

> [!IMPORTANT]
> Ніколи не порушувати це правило. Жодної багатозадачності на рівні деплой-сесій. **Один коміт-цикл → один деплой → один тестер.**
